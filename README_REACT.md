# React UI + FastAPI backend

This adds a React frontend and a FastAPI backend on top of the SAME agent logic used by the
CLI (`app/basic_agent.py`) and the original Streamlit app (`app/ui/streamlit_app.py`) — the
LangGraph pipeline, database, taxonomy and relevance scoring are all unchanged. Both UIs can
run side by side; they share one SQLite database.

## Run it

**Terminal 1 — backend (FastAPI):**
```bash
source .venv/bin/activate          # the same venv as before
pip install -r requirements.txt    # picks up fastapi/uvicorn
uvicorn api.main:app --reload --port 8000
```
Visit http://localhost:8000/api/health to confirm it's up, and http://localhost:8000/docs for the
interactive API explorer (auto-generated by FastAPI).

**Terminal 2 — frontend (React):**
```bash
cd frontend
npm install
npm run dev
```
Open http://localhost:5173. It talks to the backend at the URL in `frontend/.env`
(`VITE_API_BASE`, defaults to `http://localhost:8000`).

## What's in `api/`
Thin HTTP wrappers around the existing `app/` package — no business logic lives here.

| Route | Calls |
|---|---|
| `POST /api/auth/login` | `repo.create_or_get_user` |
| `GET /api/taxonomy` | `app.taxonomy.TAXONOMY` |
| `GET/PUT /api/users/{id}/preferences` | `repo.get_preferences` / `set_preferences` |
| `GET /api/users/{id}/digest` | `repo.get_digest` |
| `POST /api/users/{id}/refresh` | `run_pipeline` (the LangGraph pipeline — can take a minute) |
| `GET /api/users/{id}/saved`, `POST .../articles/{id}/save` | `repo.list_saved` / `toggle_saved` |
| `POST /api/users/{id}/articles/{id}/feedback` | `repo.set_feedback` |
| `POST /api/users/{id}/assistant` | `NewsAssistant.answer` |

Sign-in is still just a username (same as the Streamlit app) — proper password accounts are a
planned next step, not built yet.

## What's in `frontend/`
Vite + React + Tailwind, no component framework beyond `react-router-dom`. Pages mirror the
Streamlit tabs: Digest (`/`), Saved, Assistant ("Ask the News"), Preferences ("My Topics").
`src/api/client.js` is the only file that knows the backend's URLs.

## Authentication (added after the initial build)

Real accounts now exist: passwords are hashed with bcrypt, and logging in issues a session
token (`Authorization: Bearer <token>`), stored by the frontend and checked on every request.
Every `/api/users/{user_id}/...` route verifies the token's owner matches `{user_id}` - one
user can no longer view another's data by editing the URL.

**Migrating existing accounts:** usernames created before this feature (no password set) are
not locked out. The first time that username is used with **Sign Up** (not Log In), the server
treats it as claiming the existing account and sets its first password - its preferences, saved
articles and history are untouched.

New endpoints: `POST /api/auth/signup`, `POST /api/auth/login`, `POST /api/auth/logout`,
`GET /api/auth/me`. See `app/services/auth_service.py` for the actual hashing/session logic -
it's deliberately separate from the HTTP layer so it's unit-testable without spinning up FastAPI.
